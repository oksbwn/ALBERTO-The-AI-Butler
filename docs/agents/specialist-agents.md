# Specialist Agents

Specialist Agents in Alberto are modular, domain-specific agent presets defined in `backend/alberto/services/agents.py`. Each specialist operates with targeted system prompts, dedicated tool allocations, and model bindings.

---

## 1. Specialist Archetypes (Flavors)

When creating or modifying an agent preset, you specify its behavioral flavor:

| Flavor | Execution Behavior | Typical Applications |
| :--- | :--- | :--- |
| **`agent`** | Multi-turn ReAct reasoning loop with dynamic tool invocation. | Research analysts, home automation assistants, interactive problem solvers. |
| **`router`** | Evaluates inputs against categories or criteria, emitting branch targets without tool calls. | Intent classification, message routing, ticket triage. |
| **`evaluator`** | Validates outputs generated by other nodes against compliance, accuracy, or format rules. | Quality gates, security egress checks, markdown format verifiers. |
| **`summarizer`** | High-throughput concise compression node. | Meeting minutes generators, conversation turn condensors. |

---

## 2. Configuration Schema

Specialist agent definitions are stored as JSON specifications in the `agents` database table:

```json
{
  "id": "ag_01j7xyz123",
  "project_id": "prj_default",
  "name": "code_auditor",
  "config": {
    "flavor": "agent",
    "model": "ollama:qwen2.5-coder:7b",
    "temperature": 0.2,
    "max_tokens": 4096,
    "system_prompt": "You are Alberto's Senior Code Auditor. Review code for security vulnerabilities, style consistency, and performance bottlenecks.",
    "tools": [
      "git_diff",
      "read_file",
      "run_linter"
    ],
    "middleware": [
      "secret_redaction_middleware",
      "pydantic_validator_middleware"
    ]
  }
}
```

---

## 3. Specialist Execution Lifecycle

When invoked inside a workflow or via coordinator delegation:

1. **State Initialization:** An isolated sub-graph is provisioned with the agent's system prompt and tool whitelist.
2. **Tool Execution Loop:** The model evaluates the task and makes tool calls as needed.
3. **Structured Emission:** Once reasoning concludes, the specialist packages its findings into a typed result schema (`AgentResult`).
4. **State Cleanup:** Ephemeral variables are cleared and the execution trace is committed to the observability store.
